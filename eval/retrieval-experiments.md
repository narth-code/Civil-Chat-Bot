## Agent integration notes

Changes the agent side (`app/rag/agent.py`, not edited here) must account for:
- Unscoped `hybrid_search` (no `document_ids`) now ranks all current manuals in one list by vector similarity. It no longer reserves up to three slots per manual, so results may come from one manual only. Scoped calls (`document_ids=[...]`) are unchanged.
- `retrieval_per_document_quota` and `retrieval_fts_any_term` settings are removed. Remove `RETRIEVAL_PER_DOCUMENT_QUOTA` and `RETRIEVAL_FTS_ANY_TERM` from `.env` if they are set; they are no longer read.
- `retrieval_fts_weight` (default 0.0) is the only FTS switch. A positive value enables the AND full-text leg. `RETRIEVAL_FTS_WEIGHT` overrides it.
- `fts_tsquery(query)` now takes one argument and joins with AND. Nothing in `app/` calls the removed `any_term` argument.
- `diversify` is still exported with its signature, but `hybrid_search` no longer calls it.
- `fuse` returns `found_by` tuples sorted by list name, which is `(full-text, vector)` when both legs hit. Scores and ranks are unchanged.
- `hybrid_search` keeps its signature. Results still carry `chunk_id`, `fts_rank`, `vector_rank`, and `rrf_score`. No rerank score is present (no reranker).
- Retry (`k * 2`) and section-ref lookups (`find_section_ref`, `get_provision_chunks`, `normalize_section_ref`) are unchanged.
- Latency: warm p50 84 ms, p95 124 ms for `hybrid_search` on the golden questions. The embedder holds about 1.15 GB of CUDA memory.

## Relevance gate calibration (agent `grade_kb`)

The agent gates KB evidence on the top reranker logit (`RetrievedChunk.rerank_score`) in three bands. At or above `retrieval_relevance_threshold` (1.0) the evidence is accepted without the LLM grader. From `threshold - retrieval_grader_margin` (1.0 - 2.0 = -1.0) up to the threshold, the LLM grader decides from the facts. Below -1.0 the evidence is weak with no grader call. With no score (reranker unavailable), the LLM grader decides. Calibration script output: 128 rows, top-logit per question.

| Set | Label | Min | Median | Max | Threshold 1.0 outcome |
|---|---|---|---|---|---|
| Golden positives | answerable | -2.37 | 5.15 | - | recall contribution |
| Golden negatives | absent topic | - | - | -3.44 | all rejected |
| Eval positives | answerable | -0.62 | 2.40 | - | positive recall 92.2% overall |
| Eval negatives | absent or out-of-scope | - | - | 0.20 | all rejected |

Chosen bands: threshold 1.0 for automatic acceptance, and a grader band down to -1.0. Positives below 1.0 (eval minimum -0.62, golden minimum -2.37) reach the grader instead of being rejected by the gate alone. The automatic-weak floor of -1.0 keeps the calibrated negatives out of the grader: golden negatives max -3.44, and the abstain/filter cases in the full eval run `data/eval/20261010T053549048001Z.json` graded -1.39 to -4.55 with no grader call. The eval-negative maximum (0.20) lies inside the band, so the grader decides those; the same run abstained on every abstain case. Lowering the margin admits more negatives to the grader; raising it sends more answerable questions past it.
